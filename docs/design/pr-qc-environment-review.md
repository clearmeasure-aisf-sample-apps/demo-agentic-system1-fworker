# Review of pr-qc-environment.md (Opus 5.5, 2026-10-11)

Verdict: ready after the BLOCKERs (1 to 5) are fixed. Apply every finding below to the design.

1. BLOCKER, 4.1 and 6 (Auth). `Auth.AuthorizeVerb` (Auth.cs:83) sets `kind = "own-item"` for every role except inspector. `Plant.OnVerb` "accept" (Plant.cs:196) then sets `ownerOf[item]` to the QC worker, so a QC accept takes the item away from its owner. `release` is in `QcVerbs`, and `OnVerb` "release" (Plant.cs:200) removes `ownerOf` and every assignment of the item. Fix: in 6, map role `qc` to kind `qc-env`, track it in a separate `qcOf` map, take `release` out of `QcVerbs`, and add a Tier 1 test that a qc token's accept/release leaves the owner unchanged.
2. BLOCKER, 3.2, 3.5 and 4.1 (Plant). `Plant.Plan` (Plant.cs:130-164) builds assignments only from the sweep's `offers` and drops any unaccepted one the sweep did not ask for. A Start-created `qc-env` assignment is dropped on the next sweep, and 3.5 says the sweep never offers QC. Fix: add a separate `Plant.PlaceQc()`/`Tick` path that `Plan` never prunes (key `item|qc-env|qc|pr`). On gateway restart, rebuild it from the QC records.
3. BLOCKER, 3.1 (state comment). `Get-State` parses with the regex ```` (?s)```json\s*(.*?)\s*``` ```` (Board.ps1:115). JSON does not escape backticks, so a build log or `fail.reason` containing three backticks ends the fence early and corrupts the item's whole state. Fix: keep `log_tail` out of the state comment (gateway memory only), and replace backticks in every worker-supplied string that is persisted.
4. BLOCKER, 4.3 step 9 and 3.1. A heartbeat every 60 s that renews `lease_until` in the state comment costs a paginated GET plus a PATCH each time, races sweep and page writes (`Save-State` rewrites the whole comment; only `Use-ItemLock` protects it) and burns GitHub API quota. The page poll every 3 s with a fresh GitHub head read (2.4) and a pwsh spawn per poll adds to that. Fix: keep lease, heartbeat, `last_touch`, probe results and status in gateway memory (Plant). Persist only state transitions. Answer `/status` from memory. Read the head fresh only on POST and on GET of the page itself.
5. BLOCKER, 3.6 against 6. The owner-events paragraph says the owner "takes no action" on `qc.*`. Under `peer-approved`, someone must call `merge` once the human approval arrives, and `merge` refusing `qc-approval-missing` (10) leaves the owner with no retry trigger. Fix: route `qc.approved` (from `pr.reviewed`) to the owner as a trigger to retry `merge`. Say in factory-follow-through/functional-testing that 10 `qc-*` means wait for that event, not park.
6. SHOULD-FIX, 4.6 and 1.3 (confirmation). With anonymous clicking, the "explicit confirmation checkbox" for untrusted authors, for `secretPatterns`/`aiDirectedText` hits, and the `protected_paths_ack` can be ticked by anyone holding the link. Fix: require the confirmation from the dashboard (operator token) only; the link page shows "needs operator confirmation". Also check the head commits' authors/pusher, not only the PR author.
7. SHOULD-FIX, 3.3 `/go` and 4.3 step 8 (open redirect, SSRF). The worker-reported URL feeds a redirect and a gateway GET. Fix: allow only `http`/`https`, no userinfo, no redirect following in the probe. Resolve DNS once, check the resolved IP against the rules (no DNS rebinding), and connect to that IP. Require the URL host to equal the `address` the worker declared when it registered (shown on the dashboard). The remaining blind private-range probe on `/_healthcheck` is acceptable under the decisions.
8. SHOULD-FIX, 2.2 (header/IP trust). The "first `X-Forwarded-For` hop" is set by the client. Fix: use ASP.NET `ForwardedHeaders` with `KnownProxies` and take the right-most untrusted hop. Ignore the header when `qc.trustProxy` is false.
9. SHOULD-FIX, 2.3 and 6 (exit/HTTP mapping). `Program.cs:124` maps 20 to 503 and 30 to 500. The design wants 429 for `rate-limited`, 403 for `bad-link` and 410 for stale/expired. Fix: state that the `/qc/*` handlers use their own reason-code to status table, not the verb mapping. Make the page principal `qc-click` an explicit branch in `AuthorizeVerb`.
10. SHOULD-FIX, 6 (leftover). `QcVerbs` lists `qc-teardown-ack`, which is defined nowhere, and 4.5 omits it. The verb is `qc-stopped`. Drop it. 2.3 mixes the link nonce and the page nonce: name them `link_nonce` and `page_nonce`.
11. SHOULD-FIX, 3.2 (state machine). `stale` (3.5, 8.3) and `waiting` are used but missing from the table. 2.3's "existing" rule makes a second Start on a torn-down or failed record for the same SHA a no-op, contradicting "PR returns to available". Add `stale`. Define Start on a `torn-down`/`failed` record as a new attempt. Reset and relaunch always mint a new assignment id, so the old 12 h item token (Plant.cs:119) dies.
12. SHOULD-FIX, 3.4 (journal). `Verb_journal` takes only a fixed event list (Journal.ps1:64). `Get-JournalText` has no `qc-*` texts and no "cap reserve of 3 / extra slot" logic (Journal.ps1:46). List these as changes in step 3. Put `fail.reason` and the log tail into journal comments only as fenced, backtick-stripped, `@`-escaped text. HTML-escape the PR title and log on the page and dashboard.
13. SHOULD-FIX, 4.3 steps 6 and 9 (worker runtime). The default `dotnet run --no-build` lacks `-c Release` after a Release build. A Claude subagent cannot loop heartbeats for 8 h: token cost, Bash tool timeout and process reaping. Fix: add `-c Release`. `qc-local.ps1 run` detaches the app (setsid) and starts a `qc-local.ps1 watch` process that heartbeats without the model. The subagent ends after `ready`; a teardown/reset event wakes the main thread to run `stop`.
14. SHOULD-FIX, 4.4 and 4.6 (credentials within reach; acceptable under decision 2 but say it). `env -i` does not stop PR code from reading `~/.local/share/factory-worker/state` (owner and inspector item tokens, the long-lived `w1.` worker token), `~/.claude`, or the keyring through the session bus. A worker registered `owner,inspector,qc` hands PR code an inspector token that can `approve-pr`. Recommend in the profile text a separate OS user or a `qc`-only worker registration. Add these paths to the Tier 3 pass criteria.
15. SHOULD-FIX, 3.1 (privacy). The state comment is readable by anyone who can read the issue. It would publish `url` (internal address) and `requested_from` (client IPs). Keep both in gateway memory only.
16. NIT, 4.2 and 5. The connect prompt is generated in the browser and not stored. "Worker row shows whether a profile is set" needs the worker to send `qc_profile=1&qc_address=...` at registration. Add that to the registration contract.
17. NIT, 7.1. `Get-Cfg` applies `FACTORY_TIMING_*` overrides only to `timing.*` keys (Core.ps1:30). Put the `qc` durations under `timing`. Make `qc.allowLoopbackForTests` refuse to load when `FACTORY_PUBLIC_URL` is not loopback.
18. NIT, 4.4. With `HOME=E/home`, every environment restores NuGet from scratch, which threatens the 8 min cap. Record restore time in step 0. Do not share a writable package cache with PR code.

Missing failure modes (add to 8): GitHub API rate-limit exhaustion caused by QC polling; gateway restart while assigned/building (no Plant assignment exists, worker still holds a valid token); two pages posting Start at the same moment (needs `Use-ItemLock` around record creation); the worker's app outliving its session (orphan processes and ports); webhook port exposure (`/qc` must never be served on the hook port; Program.cs already blocks it, state it as an invariant); item token expiring at 12 h with an 8 h lifetime plus relaunch (lifetime plus relaunch must stay under the TTL).

Test plan gaps (add to 7): qc accept/release does not change ownership; a Start survives the next sweep's `Plan`; three backticks in a log do not corrupt state; concurrent heartbeat and sweep writes do not lose fields; XFF spoofing does not bypass the rate limit; a probe target that redirects or DNS-rebinds is refused; `/go` refuses a URL host that differs from the declared address; PR title and log are escaped on the page and dashboard; an anonymous link cannot tick the trust confirmation; a push by an untrusted collaborator to a trusted branch is caught; a restart while building recovers; an owner retries `merge` after a `qc.approved` trigger.

Implementation order (9): step 4's "Start required / assignment" scenarios need step 5 (Plant); move the `qc-env` part of step 5 before step 4, or limit step 4's tests to the `requested` state. Steps 5 and 6 both claim the heartbeat/lease: assign it to one step. Step 8's connect-prompt section needs the dashboard of step 9, which exists only in factory-worker-next: port the dashboard to factory-worker as an explicit step 0b, or build on factory-worker-next. Step 1's "fork refused" scenario includes a `qc-request` check that needs step 6. Step 2's webhook effects (editing the offer comment) need step 3: swap steps 2 and 3.
